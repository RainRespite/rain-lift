## 方案比较与选择

旁路组元数据需要 sessionID+movementID+setID 和多存储事务，结束、恢复、身份拆分更复杂。选择组内 load 扩展，session 内体重基准；训练一次 setItem 提交组及语义。个人档案独立 rainlift.body-profile.v1。完整恢复跨 key 使用持久化 undo journal，写入前保留完整副本，失败/重启回滚；未恢复完成前阻止应用读取写入。

复查补充：旧版已经打开的页面不会执行新版陈旧写入保护，因此只改格式号不足以阻止旧代码写回旧 key。新版首个新训练写入 rainlift.web.v2，之后优先读取此权威分区；类型首次写入 rainlift.exercise-meta.v2，优先于旧类型 key。两个旧 key 留存归档。原始历史复制到新权威训练分区时原值、名称、ID 和时间不变；不是清空重建。旧页面后续对旧 key 的写入不会覆盖新分区，也不会被静默合并。完整备份保存六个分区（新旧训练、新旧类型、健康、档案），空分区也显式为 null。

|记录|权威字段|set.weight|兼容行为|
|---|---|---|---|
|旧无 load|原 weight/reps/date|原始含义不变|按已有类型及旧本次体重解释，未确认不拆分|
|新版 external/assisted/unknown|load.mode + weight|该模式记录重量|模式随组固定|
|新版 bodyweight_plus_extra|load.bodyWeightKg、extraWeightKg|等于 extraWeightKg，仅新版兼容投影|不再走旧差额路径；null 体重允许保存|

新版 session 含 loadSchemaVersion:1 和 bodyWeightSnapshot；每个新组含 load.schemaVersion:1、mode、unit。bodyweight 还含体重、来源修订及更新时间。仅在新 session / 写入 load 时将训练 version 升为 2，复制到新权威分区；旧历史不逐组迁移或重解释。旧代码 validate 会拒绝 version:2。升级时已有的旧 active 继续使用旧语义直到结束，不在训练中途转换输入含义。最低完整恢复版本 v1.8.2。

legacyLoadTypes 保存旧 movement 的语义快照，设置类型/默认规则前固定旧含义。用户明确为某次旧训练确认体重时才允许相应自重差额解释；未来类型更改不会撤销既有确认。训练单独恢复时，仅逐字相同 session 可保留旧确认关联；其他旧确认及类型快照隔离到 before-training-restore，不绑定同 ID 的不同内容。

profile.current 保存自包含当前值与 revision ID；history 是实际变更事件，不是每日测量。删除当前历史可保留独立当前值或明确清空，不回退。体重 0.01–1000 kg、身高 1–300 cm，最多两位小数；额外重量沿原范围 0–10000 kg。更新时间只代表资料更新。

## 接口、流与测试切片

- body-profile：validateProfile / ProfileRepository.update / removeRevision / snapshot；同值幂等、陈旧写入拒绝。
- load：validateLoad / makeLoad / resolveLoad / suggestedLoad；数据→固定模式→UI/报告，旧原值与新版额外分组隔离。
- data：start 可传快照，record 可传 load，validate v1/v2；组与 load 同 key 原子写入。所有页面入口与工具入口共用。
- backup：exportFull / parseFull / restoreFull / recoverRestore；各分区全验证→预览→完整 before 副本→journal→写入→提交；失败回滚，重启先恢复。
- body-ui：档案编辑/历史、当前训练引用与已保存组体重更正、完整导出恢复；health-ui 仅传入 profile 给报告。
- 测试依次覆盖档案持久化和幂等→新组 0/5/null 与旧语义→快照和编辑/恢复→混合报告→完整恢复故障→真实页面合成浏览器操作；真机只列待验收。
