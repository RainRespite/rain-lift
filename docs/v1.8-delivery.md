| 能力 | 实际行为 |

## 2. 排序问题定位与修复

审计证据见 [v1.8-audit.md](v1.8-audit.md)。旧版已复现：未显式选择动作时，首项重排会令当前动作隐式切换；管理重渲染可能丢失未失焦的合法重量、备注。没有复现“所有固定计划排序都存错”，因此不作此结论。

v1.8 使用明确的“调整顺序 → 目标位置”菜单，动态列出第一位至最后一位。移动按动作或本次 movement 的身份定位，移动前固定当前选择并保存合法输入；失败时保留当前页面与输入，不虚报成功。菜单适用于触控，无需拖拽。

固定计划只改草稿，菜单确定后立即更新草稿预览，仍需保存整个计划才持久化。关闭或取消编辑不改原计划；其他计划、动作 ID、历史训练不变。正在训练的排序只更新本次训练，保留已记录组、备注、选中动作及休息截止时间；仅主动确认“更新固定计划”才同步未跳过的动作与顺序。

## 3. AI 报告重构

全历史分析排除最近删除、进行中、未结束、无有效组、无效时间及未来记录。动作按可信 ID/单位比较，历史快照保留原名；同名独立动作使用可读标签区分，未解决的身份冲突不绕过原保护。

最近两次优先比较相同重量下对应记录组的次数，同时展示各自组数、重量与次数组合；历史基线、全期和近期范围提供长期背景。有连续三次可比较记录时，只描述对应次数的上升、下降或持平，不将它确诊为疲劳、停滞或恢复问题。没有热身/正式组、RPE/RIR、动作标准等结构化字段，就不推断这些事实，也不把实际记录组数称为有效增肌组数。

会话开始到结束的差值不作为实际训练时长，组间记录间隔不作为真实休息。默认报告省略训练总时长；异常会话只作一次提示，不修正真实时间戳。

健康内容复用已经导入的实际健康记录与来源隔离汇总。按可用情况展示睡眠、HRV SDNN、静息心率、运动时长、已记录运动心率及必要活动量；步数样本不冒充全天总量，导入运动时长可能包含暂停，最近心率摘要按真实开始时间选取。无数据日期不占位，较早记录明确注明不能代表当前恢复。没有可用健康数据时，只写：“尚未导入可用健康数据，本次仅分析训练记录。”不计算恢复分数。

精简长度以 1500～2500 汉字左右为目标，不以硬截断丢弃动作关键证据。动作或来源特别多时可能超过目标；所有有效记录仍参与统计，详细模式和 JSON 可审阅完整分析材料。

## 4. 自重、器械与辅助负重

“引体向上”记录的 `68 kg`、“龙悬”的 `68/73 kg` 按用户已确认的自身体重解释，**不是额外负重**。同一次动作存在不同体重记录时，保留原值并提示核对，不猜测原因。体重增加本身不代表力量进步；组数不同时不能直接用总次数比较力量。

动作类型在“设置 → 健康与 AI → 动作负重类型”独立设置。默认匹配只使用精确可信身份、确认名称或显式改名谱系，不进行模糊名称合并。同名不同 ID 可分别修改；身份冲突强制保持未确认，整理前不能借元数据绕过保护。

器械/外部负重按真实重量与次数描述。辅助负重表示外部帮助，辅助减少与器械加重的含义不同；未确认类型只描述记录，不擅自套用外部负重结论。“龙悬”不被推断成某种特定器械或技术动作。

`dist/data.js` 与 `dist/health.js` 没有改变原存储结构。类型文件最大 512 KiB、最多 10,000 条，重复身份/单位、非法类型和错误版本会拒绝；损坏、配额与过期页面写入不覆盖当前类型数据。无匹配身份的导入配置不会凭名称应用到其他动作；类型恢复前副本与损坏 raw 可单独导出。

训练、健康、动作类型需要分别备份。旧训练备份依旧可以单独恢复；恢复训练不会清空独立健康或类型存储，但未在当前训练数据出现的类型条目不参与分析。自动化对操作前后训练、健康原始存储字符串做相等验证；没有在真实历史上执行恢复或删除来证明兼容性。

## 9. 浏览器验证与 iPhone 验收指南

本轮在独立本地 origin 使用合成数据，已实际验证 v1.7 缓存升级保留组、390 / 320 px 排序与输入保留、固定草稿取消/保存/刷新、真实文件选择器导入、精简复制、详细预览及 TXT/JSON 下载。最终320 px页面 clientWidth/scrollWidth 均为305，已消除原8px溢出。随后停止本地HTTP服务并确认连接失败，浏览器仍能缓存重开、生成包含训练/健康/类型的报告，排序保存后刷新也正确。该结果属于服务不可用时的缓存验证，不等于真机飞行模式。逐项记录见 [browser-validation.md](../qa/v1.8/browser-validation.md)，最终截图见 [position-final-320.jpg](../qa/v1.8/position-final-320.jpg) 和 [report-320.jpg](../qa/v1.8/report-320.jpg)。

本地启动：

```sh
python3 -m http.server 8768 --bind 127.0.0.1 --directory dist
```

访问 `http://127.0.0.1:8768`；新 localhost origin 与日常线上网址存储相互独立，不能通过换网址获取原历史。仅在隔离 origin 使用合成测试文件。

本轮没有生产发布，日常 iPhone 不会仅因本地文件变更就得到 v1.8。未来经用户明确授权发布到原入口后，按 [mobile-update.md](mobile-update.md) 执行以下真机检查：

1. 在原主屏幕入口分别导出训练、健康；v1.8 已设置的动作类型另行导出。记录历史条数、最近一组原值及当前网址，不清理站点数据或删除原图标。
2. 保存/关闭计划草稿，联网主动检查更新；新版就绪后使用应用提示刷新，确认设置显示 1.8，原历史、进行中记录、休息计时和健康来源仍在。
3. 固定计划测试末移首、第五移第二、取消不保存、保存后重开和刷新；检查其他动作相对顺序及其他计划不变。
4. 在专用测试训练中记录一组，填写尚未失焦的合法重量和备注后排序；检查组记录、选中动作与计时保留。确认临时排序不改固定计划，仅主动更新时同步。
5. 生成报告检查超过 7 天的历史参与、自重含义、68/73 差异、缺失健康一句说明；切换详细、复制和分别导出 TXT/JSON。iOS 剪贴板或下载权限需实际核对。
6. 确认离线缓存已就绪，再在真机飞行模式重开并生成报告；备份恢复仅在安全测试环境验证，不为验收覆盖日常真实记录。
