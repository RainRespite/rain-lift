# Rain-Lift v1.9.4 交付与恢复

## 本轮结果

主类从训练计划和本次训练里移出，集中到新的「动作库」页面管理；仍然只给自己创建的动作分类，不内置任何动作目录，也不新增存储分区。

| 需求 | v1.9.4 行为 | 代码位置 |
| --- | --- | --- |
| 在动作库里分类 | 底栏新增第 4 个标签「动作库」，按主类分组列出所有动作。点动作打开「设置主类」，六个打底类加自定义类，已选后可「清除」。未分类的动作归入最后的分组「无主类」。 | [底栏](app.js#L34)、[动作库页](app.js#L533)、[分类弹窗](app.js#L540) |
| 计划里不再分类 | 编辑计划与「调整本次训练」的动作行只显示分类标签，动作设置弹窗没有主类字段，提示「主类在底栏「动作库」里设置。」。训练中的「添加动作」只负责挑动作。 | [动作设置](app.js#L285)、[同步](data.js#L78) |
| 动作库汇总所有动作 | 动作库 = 计划中的动作 + 进行中训练的动作 + 库内独有动作，按动作编号去重，同一动作只出现一次。不属于任何计划和本次训练的动作标注「仅在动作库」。 | [汇总与去重](data.js#L46)、[库内新建](app.js#L549) |

| 分类跟着动作走 | 在动作库改主类或改名，会同步到动作库条目、所有计划和正在进行的训练；已完成的训练保留当时的分类，和重量、组数一样是快照。旧编号关联冲突时先要求整理历史。 | [分类同步](data.js#L78)、[改名同步](data.js#L85) |
| 自定义类自动收放 | 候选 = 六个打底 + 当前仍被使用的自定义名，按中文排序；没有动作再用的类自动消失，不维护单独清单。清除会把 `group` 字段整个删掉，不留空字符串；名称写入前归一，超 24 字提示。 | [候选派生](data.js#L70)、[归一](data.js#L48) |

## 数据与兼容

- 动作库保存为训练数据里的可选 `library` 数组，和计划、历史同属训练分区，因此训练单独备份与六分区完整备份都会自动带上它，无需新增存储分区或迁移。
- 校验对 `library` 按「缺省即可、存在则逐条校验」处理：必须是动作对象数组且编号不重复；旧数据没有 `library` 时不会凭空补出。
- 训练 `rainlift.web.v1` / `rainlift.web.v2`、健康、动作类型、身体档案六分区完整备份 v1 全部保持原样，备份 `minimumAppVersion` 仍是 `1.8.2`。
- v1.9.3 收到带 `library` 的备份时只校验已知字段，未知的 `library` 原样保留，可继续记组并再次导出；再回到 v1.9.4 后动作库、分类和新增组完整回来。
- 训练单独导入仍整体替换训练分区，目标端原有动作库不会残留；这是训练文件「完整替换」的既有语义。

## 发布状态与恢复

本轮改动位于分支 `codex/exercise-library-v1.9.4`（基线 `main` 的 1.9.3 提交），尚未合入 `main`、未推送、未发布；参赛版工作区与站点未改动。发布前需按既有流程确认原手机入口与参赛版互不影响。

回退到 v1.9.3 不需要数据迁移：旧版会忽略训练数据中的 `library`，已写入的 `group` 字段继续按 v1.9.3 的规则显示和同步，`library` 原样保留；再升级回 v1.9.4 时动作库直接可用。

## iPhone 待真机验收

1. 从原主屏幕图标联网打开，等新版缓存后按提示刷新，设置核对版本为 1.9.4。
2. 核对底栏为四个标签，「动作库」在第 4 位。
3. 动作库点一个动作设置主类，核对分组移动、计划行标签同步。
4. 动作库右上角「＋」新建一个动作，核对显示「仅在动作库」；再在计划「添加动作」里选中它，核对计划使用同一动作且动作库没有多出一条。
5. 编辑计划与本次训练，核对弹窗不再出现主类输入，只显示标签和「主类在底栏「动作库」里设置」。
6. 开始训练后切到动作库改主类，核对本次训练和计划同步；已完成的历史保留原分类。
7. 自定义一个类并给两个动作使用，清除其中一个后该类仍在候选；清除最后一个后该类消失。
8. 刷新页面，核对进行中的训练、计划和动作库分组原样保留。
9. 导出完整备份到「文件」，在隔离入口或另一浏览器导入，核对动作库与分类随行；飞行模式再核对一次离线可用。
