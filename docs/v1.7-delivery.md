## 数据结构与兼容性

| 用途 | 本地 key / 格式 | 兼容规则 |
| --- | --- | --- |
| 原训练数据 | `rainlift.web.v1` / `rainlift-web`, `version:1` | `data.js` 与 v1.6 字节一致；旧网页与 Swift 原生备份恢复逻辑保留 |
| 新健康数据 | `rainlift.health.v1` / `rainlift-health`, `version:1` | `timeZone`, `records`, `lastImportAt`；不写入训练 key |
| 健康交换文件 | `rainlift-health`, `version:1` | `timeZone`, `exportedAt`, `records`；健康导出可重新导入 |
| AI 分析材料 | `rainlift-ai-report`, `version:1` | `period`, `training`, `health`, `subjectiveRecovery`, `limitations`, `instructions`；不能用作恢复备份 |

**界面 v1.7 与这三个格式版本 1 是不同概念。** 健康与训练必须分别导出备份。

健康记录保存 `id/type/source/start/end/timeZone/unit/value/aggregation`，睡眠另有 `stage`，运动另有 `workoutType` 和可选 `heartRate`。来源身份由真实 `name` 与可选真实 `bundleId` 共同确定。同源同 ID 内容冲突拒绝；语义重复也去重，避免重复导出产生多份记录。无法区分的完全相同样本保守合并，可能少计；不猜测补数。

自然日趋势按界面所示时区统一分日，最近一次确认导入的顶层时区成为当前展示时区；原始记录时间偏移与时区不改写。滚动 24 小时步数不混入自然日。跨日步数不按时间比例分配。睡眠按同源连通片段结束日归属，不推断跨缺口片段属于同一夜；有效睡眠取并集，在床/清醒不计入。阶段冲突不输出可信分期；显式睡/醒矛盾不输出可信总时长。

健康写入先准备完整新状态，`setItem` 成功后才更新内存；失败保留原状态。损坏存储阻止写入，仍可导出原始内容。检测到其他页面已保存的修改时拒绝过期写入；此检查不是跨页面原子锁，仍应避免同时在多个标签页编辑健康数据。所有操作只针对当前 origin 的本地数据。

## 使用方法

先按 [apple-health-shortcuts.md](apple-health-shortcuts.md) 配置 iPhone 快捷指令，从少量真实步数样本开始。保存到“文件 → 我的 iPhone”，在“设置 → 健康与 AI”选择 JSON，查看预览后确认。Watch 没到货不影响此路径。

生成报告：打开“健康与 AI → 生成 AI 分析报告”，审阅本地预览，点“一键复制”后自行粘贴到已有 ChatGPT 对话；也可导出 JSON 或纯文本。若系统拒绝剪贴板，长按报告文本全选复制。复制、下载、生成都不会向 ChatGPT 发送请求。

报告包含最近 7 个自然日（含今天）的已完成训练次数、同 ID/同单位的逐组重量次数及首末变化、实际记录组数、会话经过时长、计划休息与组间记录间隔、健康趋势、来源、缺失说明及分析提示。删除/进行中/未来/全零组训练不计入；身份冲突动作不作首末比较。自由备注默认不导出。

现有记录无法确定有效刺激组数、实际休息执行时长、RPE/RIR、疲劳、酸痛与主观恢复，所以报告明确列为缺失。GPT 的任务是说明依据与局限、给出下一次训练建议，用户自行决定是否采用；报告没有修改计划授权。

本地启动（从项目目录运行）：

```sh
python3 -m http.server 8767 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8767`。localhost 与线上站点的数据独立；不要通过换网址寻找原有训练历史。测试文件 `tests/fixtures/apple-health.synthetic.json` **只供隔离测试**，不能作为真实健康记录导入日常站点。

## 实际浏览器验证

仅在隔离 origin `http://127.0.0.1:8767` 使用 5 条明确标注的合成健康记录，以及一组测试训练 `40 kg × 8`，未访问真实训练站点的存储。

- 导入文件后出现新增 5 条、重复 0 条的确认预览；确认后记录、来源和日趋势可见。
- 浏览器实际发现原有两个 WebMCP 工具，并成功调用 `record_training_set`；界面出现对应组与休息计时。非法输入通过自动化回调测试拒绝。
- 完整缓存更新后，主动刷新仍保留进行中组记录与 5 条健康数据。
- 终止本地 HTTP 服务后重载成功，仍可结束测试训练并生成报告。这是**源站不可用的离线缓存验证**，不是 iPhone 飞行模式或锁屏后台验收；浏览器 `navigator.onLine` 在此场景仍可为 true。
- 390 × 844 视口下查看报告对话框、实际下载 JSON 和 TXT、主动复制成功；检查下载内容为 1 次训练、1 组、7 日健康摘要，缺失有效训练组为 null；浏览器未见脚本错误。
- [报告截图（合成数据）](../qa/ai-report.synthetic.jpg)。

没有对真实数据执行恢复、删除、清站点存储或迁移；未进行生产部署。浏览器测试覆盖的数据规模较小，不代表所有 iPhone/iOS 版本已验证。

## 下一阶段建议

Apple Watch 到货后，先在同一真实设备上逐类核对来源、单位、时间范围与健康 App 可见记录：先步数，再睡眠和静息心率，最后 SDNN/运动心率。保留一小份真实导出和本地导入摘要作人工对照，特别检查重复来源与睡眠片段。不要把样本之和强行校准成 Health 首页总量。

完成 iPhone 主屏幕、飞行模式、导出恢复与容量检查后，再考虑减少文件选择步骤的免费手动快捷操作。自动后台同步、原生桥接、任何外部分享或后续发布需另行确定范围；当前版本没有这些能力。
