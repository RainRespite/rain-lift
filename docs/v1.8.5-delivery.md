## 实现与数据契约

- `app.js → bodyUI.record → data.record → Repository.change` 继续承接快捷记组和手填。普通为新界面默认类型，热身、递减和力竭是本组选择，保存后复位。WebMCP 原有参数与返回结构保留，追加组按未分类处理。
- 组内可选 `performance` 保存类型、力竭标记和一份评分。精确 RPE 按 0.5 递增，精确 RIR 用 `10 − RPE` 显示。RIR 5+ 作为单独边界保存，在 RPE 视图显示 ≤5。训练根对象的可选 `effortDisplay` 随训练文件保存。关闭后隐藏训练和历史中的评分控件及标记，报告依旧按实际填报统计，关闭偏好保留已有评分。
- 有评分的组另外保存 `effortBasis`，记录评分时的重量、次数和组内参考体重。任一值改动后保留原评分，显示待确认并排除在评分覆盖外。可以确认原值适用、改为其他评分或清空。这个保护也适用于 v1.8.4 修改后再升级。
- 休息面板补注按训练、动作和组 ID 定位。目标组被撤销或被其他窗口改动时拒绝旧表单写入。只补注时保留负重、参考体重快照和计时，附加字段通过原有单次提交保存。
- 训练历史和 AI 报告分别统计普通、热身、递减、未分类、力竭标记与评分覆盖。原有全部实际记录组计数和报告比较口径继续使用。AI 报告结构版本保持 2，添加分项字段与有效评分。
- 保留 v1/v2 训练键优先级、组负重契约、六分区完整备份 v1、原恢复日志和恢复前副本。完整备份保留原头部 `minimumAppVersion: '1.8.2'` 以通过旧版的精确匹配。本轮旧版兼容实测对象为 v1.8.4。
- 更新继续在打开、返回前台或联网时检查。新版完整安装后，仅在前台、无活动训练且无打开对话框的训练首页自动载入。其他页面显示就绪提示，支持手动刷新。
- `performance.js` 由 `data.js`、`app.js`、`ai-report.js` 共用。设置版本、`package.json`、静态引用与 `sw.js` 缓存已统一为 1.8.5，`docs/` 与 `dist/` 的 17 个静态文件逐字节核对。

### 本地恢复件

- 首个候选保存在 `v1.8.5-rc.1`。正式版本使用 `v1.8.5` 标签，GitHub Pages 从 `main` 的 `docs/` 取用部署资源。源码恢复包可检出发布版本与 v1.8.4。
- 相邻目录 `rain-lift-v1.8.5-recovery-20261105` 存有原版行为的独立恢复构建、两个静态目录和 SHA-256 清单。恢复构建来自 v1.8.4 精确提交，调整了显示、静态引用和缓存标识。用以下命令可以在一个新目录重建已验证的版本。

```sh
node scripts/prepare-v1.8.5-recovery.mjs --out /absolute/new-recovery-directory --build-id 20261105a
```

每次准备新的恢复发布使用新的构建 ID。实际恢复前，先导出并保存**当时最新**的完整备份，先在隔离环境检查恢复构建、下载失败、主动刷新和离线重开。经单独授权发布恢复提交后，在原入口联网检查更新，确认版本和离线就绪，再核对训练、活动计时、最近删除、健康与体重快照。回滚出错时保留原存储和完整备份，切换回能够读取现有数据的已验证构建。线上恢复采用新的提交并保留主分支历史。
