# Rain-Lift v1.9.2 交付与恢复

## 本轮结果

只给自己创建的动作打主类，不内置任何动作目录，也不新增存储分区。

| 需求 | v1.9.2 行为 | 代码位置 |
| --- | --- | --- |
| 六个打底主类 | 动作设置新增「主类 · 选填」：背、肩、胸、腿、核心、手臂。默认不预选，界面不出现「未分类」，没选就是没选。 | [打底列表](data.js#L6)、[选择器](app.js#L291) |
| 自己再加新类 | 同一行末尾的「自定义」输入框填新类名。候选 = 六个打底 + 当前计划和本次训练中正在使用的自定义名，按中文排序；没有动作再用的类自动消失，不维护单独清单。 | [候选派生](data.js#L56) |
| 分类跟着动作走 | 改一次主类，所有计划和正在进行的训练一起更新；已完成的训练保留当时的标签，和重量、组数一样是快照。旧动作编号关联冲突时先要求整理历史。 | [同步](data.js#L63)、[计划编辑](app.js#L265)、[本次调整](app.js#L395) |
| 看得见 | 编辑计划的动作行、「调整本次训练」和「添加动作」列表在名称后显示主类标签。 | [标签](app.js#L290)、[选动作](app.js#L407) |
| 随时改随时清 | 已选类后出现「清除」单选，清除会把 `group` 字段整个删掉，不留空字符串。名称含首尾空格或多空格时写入前归一，超 24 字提示。 | [归一](data.js#L48)、[保存](app.js#L292) |

## 数据与兼容

- 训练 `rainlift.web.v1` / `rainlift.web.v2`、健康、动作类型、身体档案六分区完整备份 v1 全部保持原样，备份 `minimumAppVersion` 仍是 `1.8.2`：新字段是动作记录上的可选字符串，旧版读得懂。
- 校验按「宽松接收、写入归一」处理：`group` 允许缺省、`null` 和 1–24 字的非空白字符串，避免手改或未来标签把整个训练库锁死；写入前统一去首尾空格、折叠连续空格。
- 旧的 v1.9.1 备份导入后动作仍无主类，不批量猜测、不自动填充。带主类的备份交回 v1.9.1 代码时原样保留，不会被丢弃或改写。
- 本轮不含内置动作目录、收藏、搜索和独立备份分区；先前的目录方案完整保存在标签 `archive/exercise-library-catalog`，当前分支基于 `v1.9.1`。

## 发布状态与恢复

代码只在分支 `codex/exercise-groups-v1.9.2`（基线 `ac45a8e`）。未合入 `main`、未打版本标签、未推送远端、未发布。原手机 GitHub Pages 入口和 Sites 原版继续停在 `v1.9.1`；参赛版站点与该分支互不影响。

回退不需要数据迁移：检出 `v1.9.1` 即可，本机已写入的 `group` 字段在旧版中被忽略且保持原值。若要在其他入口试装，从本分支独立构建，保留训练、健康、档案与动作类型本地数据，并按既有流程核对版本、历史条数和离线状态。

## iPhone 待真机验收

1. 从原主屏幕图标联网打开，等新版缓存后按提示刷新。
2. 设置核对版本为 1.9.2，历史条数与升级前一致。
3. 编辑计划 → 任一动作「设置」，核对只出现六个打底主类和自定义输入，没有「未分类」。
4. 选一个主类并保存，回到计划列表核对名称后的标签。
5. 用自定义输入新建一个类，核对第二个动作的候选里出现它。
6. 在另一计划编辑同一动作，核对两个计划的标签一起变化。
7. 打开历史，核对旧训练标题与当时的组记录不变。
8. 本次训练「调整」和「添加动作」核对标签显示；在训练中改主类，确认只同步计划中的同一动作。
9. 选「清除」后保存，重新打开确认无预选且字段消失。
10. 导出完整备份到「文件」，在隔离入口或另一浏览器导入，核对主类随行；飞行模式再核对一次离线可用。
