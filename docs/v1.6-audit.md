## 已有功能与数据契约

| 项目 | v1.6 实际实现 | v1.7 需要保护的边界 |
| --- | --- | --- |
| 架构 | 静态 HTML/CSS/ES modules；`docs/` 与 `dist/` 各有一套运行文件；无运行时外部依赖 | 保持静态部署、离线读取与已有训练逻辑 |
| 界面版本 | 设置页和资源参数为 `1.6` | 界面可升级到 `1.7` |
| 训练存储 | `localStorage['rainlift.web.v1']`；`format:'rainlift-web', version:1` | **格式版本继续为整数 1**，不是 1.7 |
| 主数据 | `plans`, `history`, `active`, `rest`；可选 `deletedHistory` | 健康导入、删除和报告生成不得写入这些字段 |
| 动作身份 | 计划、动作、会话、会话内动作与组均有 ID；新建使用 `crypto.randomUUID()`；历史保存动作快照 | 相同名称不能作为动作合并依据；旧编号冲突仍通过原显式修复流程处理 |
| 时间 | 会话 `started/ended`、组 `date` 为 Unix 毫秒；休息 `end` 为绝对截止时间 | 现有记录没有完整历史休息事件，也没有 RPE/RIR 采集 |
| 已有训练能力 | 计划编辑、排序/移除/跳过/更换、重量次数记组、补录/撤销/编辑、休息计时、历史、最近删除与恢复 | 不重写或重复开发 |
| 训练备份 | 导出当前训练 JSON；导入限 10 MiB；严格验证格式、ID、数值、会话与计时引用 | 保持旧版网页备份和原生迁移路径 |
| 原生备份 | 无 `format` 且 `version:1` 时，按 Swift 2001-01-01 基准秒转换成 Unix 毫秒 | 不把健康文件送入训练恢复路径 |
| 写入保护 | clone → 修改 → validate → `setItem` 成功后更新内存；损坏存储停止写入 | 健康使用独立事务；存储失败不得确认成功 |
| 恢复保护 | 恢复前保留 `.before-restore`；动作身份修复前保留 `.before-identity-repair` | 不清除副本，不自动恢复或覆盖真实数据 |
| PWA | service worker 完整预缓存；`cache:'reload'`；成功后激活；仅清理同前缀旧 shell 缓存 | 新模块也需完整缓存；CacheStorage 清理不能涉及 localStorage |
| 更新 UI | 联网/回到前台检查；有新控制 worker 时提示刷新；保留编辑草稿，主动刷新前保存训练输入 | 不强制刷新，不清站点数据 |

训练备份目前不包含健康数据。采用独立 `rainlift.health.v1` 后仍分别导出；“导出训练备份”不能替代健康备份。浏览器按来源（origin）隔离本地存储，GitHub Pages、Sites、localhost 之间不会自动共享数据。

## WebMCP 可用范围

`app.js` 仅在 `document.modelContext?.registerTool` 存在时尝试注册：

- `read_training_state`：读取当前 `active/rest` 的结构化克隆；不含完整训练历史，不含健康记录。
- `record_training_set`：需要当前训练动作；验证重量 0–10000、次数整数 1–999 后调用现有 `record` 与 Repository，开始原有休息计时。

工具随 `pagehide` 中止，注册错误会被捕获。没有该实验 API 的浏览器仍运行 PWA；源码存在不证明特定浏览器已经启用，也不证明 ChatGPT 官方支持自动连接。v1.6 的 README 曾记录工具验证，但本轮必须以实际重跑结果另行说明。v1.7 不需要为报告生成重新实现记组工具；健康数据默认不通过 WebMCP 暴露。

## 缺失功能、冲突与最小实施范围

v1.6 没有 Apple Health JSON 协议、健康存储、导入预览、健康趋势或 GPT 可分析报告。静态 PWA 本身没有原生 HealthKit 授权桥接；本轮通过用户主动选择快捷指令导出的文件建立本地闭环。

| 潜在冲突/信息缺口 | 最小处理 |
| --- | --- |
| 界面版本与训练格式版本混淆 | 只升级 UI/cache 资源版本；`data.js` 的训练契约保持不变 |
| 恢复训练备份会替换现有训练 | 健康导入单独入口、独立 key，永不调用训练 `restore` |
| Watch 与 iPhone 重复步数、样本交叠 | 保存来源；同源去重；不同源分开；不声称重现 Health 优先级算法 |
| 自然日、滚动 24 小时、跨日睡眠混用 | 显式时区与时间偏移；独立 aggregation；睡眠按同源连通片段结束日归属 |
| 未记录的有效强度、真实休息、疲劳被“补齐” | 只报告实际记组数、会话经过时间；缺失数据明确说明 |
| 两套运行目录漂移、新模块漏缓存 | 同步 `docs/dist`，统一资源版本，增补离线缓存和更新保护检查 |
| 实验 WebMCP 被误称稳定四端连接 | 保留原工具，明确浏览器条件；本轮报告由用户手动复制/导出 |
| 手机浏览器容量/配额限制 | 文件与记录上限、全量验证、原子写入、失败不更新内存；分别备份 |

本轮最小增量：独立健康协议/存储/汇总模块、设置中的“健康与 AI”入口、确认式文件导入与指定记录删除、最近数据和 7 天按来源趋势、健康 JSON 导出、只读训练与健康报告、复制/JSON/TXT 导出、快捷指令文档和保护性测试。原生 iOS/Watch、自动后台同步、云账户、付费 GPT API、恢复评分和自动改计划均不在本轮。
