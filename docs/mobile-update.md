# 手机更新到 Rain-Lift v1.7

本指南用于让手机原有 Rain-Lift 主屏幕入口下载应用新版。线上部署完成后，手机联网打开原网址，才能获取更新；GitHub 源码上传完成不代表所有部署网址和手机缓存都已更新。发布结果请结合 [更新日志](../CHANGELOG.md)与本轮实际发布核验记录查看。

## 更新步骤

1. **保留原来的主屏幕图标和网址。** 从平常记录训练的入口打开 Rain-Lift，在“设置”查看“当前网址”，确认原训练记录可见。不要新建入口或换网址寻找数据。
2. 建议先导出训练 JSON 备份；如果该入口已有健康记录，也单独导出健康 JSON。两个备份分别保存；AI 报告不能用于恢复数据。
3. 保持联网，在“设置 → 版本与更新”点击“检查更新”。应用也会在联网打开、返回前台时检查。等待新版完整下载，出现“新版已就绪”或“刷新到新版”。
4. 保存或关闭计划/动作/组记录编辑对话框，再点“刷新到新版”；也可在设置点“刷新页面 / 载入新版”。主动刷新前会保存当前训练输入的重量和备注；不要强制中断正在保存的操作。
5. 刷新后在设置确认“当前版本：1.7”，并确认“离线使用：已就绪”。检查训练历史、进行中的训练和已有健康记录，再进入“设置 → 健康与 AI”使用新增入口。
6. 完成联网缓存后可在本人手机上测试飞行模式：重新打开应用，检查现有训练与健康记录能否查看。检查完成后恢复联网。真实 iPhone 的结果需要实际验证，桌面测试不能代替。

更新使用原站点本地存储：训练为 `rainlift.web.v1`，健康为 `rainlift.health.v1`；训练 JSON 格式仍为 `version:1`。正常更新不清理这两个存储空间，也不要求重新导入真实记录。

## 暂未看到新版

- 保持联网，确认打开的是已完成 v1.7 部署的原网址，再点“检查更新”。“已完成检查”仅表示检查完成；设置里显示的版本号才是当前页面版本。
- 若正在下载，等待下载完成后再刷新。网络或某个资源下载失败时，保留原可用缓存；重试检查更新即可。
- 保存编辑内容后，关闭并重新打开原主屏幕应用，再检查。若仍是 v1.6，核对该网址的部署状态与资源版本，保留旧版继续使用。
- **不要清除 Safari 网站数据、删除原图标、重置存储或导入旧备份来催促更新。** 如果出现数据不可见，先核对当前网址和使用环境，再处理，不要先恢复覆盖。

## 网址与记录的关系

GitHub Pages 与 OpenAI Sites 是不同来源，各自持有当前设备的本地训练和健康数据。Safari 与主屏幕应用的存储环境也可能不同。另一个网址即使已显示 v1.7，也不会自动带来原网址的训练历史。

同一入口升级后继续使用原有记录。需要换网址或换设备时，应先分别导出训练与健康备份，并在目标环境核对后手动迁移；训练恢复会替换目标训练数据，不能当作无风险的“同步”按钮。

## 健康与 GPT 的实际链路

手机应用版本更新后，健康数据仍需由用户运行 iPhone 快捷指令导出到本地文件，再在“健康与 AI”中预览并确认导入。Apple Watch 新产生的数据不会因 PWA 更新自动进入 Rain-Lift。

GPT 报告在本机生成，用户主动复制或下载后自行决定是否发送到 ChatGPT。当前版本没有跨设备记录自动同步、HealthKit/Watch 自动连接、可靠锁屏后台同步或后台上传。快捷指令配置见 [apple-health-shortcuts.md](apple-health-shortcuts.md)。
