# 手机更新到 Rain-Lift v1.8（GitHub Pages 原入口）

手机原入口已由用户于2026-11-02确认为 https://rainrespite.github.io/rain-lift/ 。本次将v1.8合入main以更新该入口，发布成功后按以下步骤载入。GitHub开发分支推送和Sites发布都不能证明这个Pages入口已更新；必须核对Pages的实际静态资源。

## 更新步骤

1. **保留原来的主屏幕图标和网址。** 从平常记录训练的入口打开 Rain-Lift，在“设置”查看“当前网址”，确认原训练记录可见。不要新建入口或换网址寻找数据。
2. 先导出训练 JSON；已有健康记录则另行导出健康 JSON。v1.8 中设置的动作负重类型还要独立导出类型备份。三份文件分别保存，AI 报告不能用于恢复数据；从 v1.7 首次升级时尚无类型备份是正常情况。
3. 保持联网，在“设置 → 版本与更新”点击“检查更新”。应用也会在联网打开、返回前台时检查。等待新版完整下载，出现“新版已就绪”或“刷新到新版”。
4. 保存或关闭计划/动作/组记录编辑对话框，再点“刷新到新版”；也可在设置点“刷新页面 / 载入新版”。主动刷新前会保存当前训练输入的重量和备注；不要强制中断正在保存的操作。
5. 刷新后在设置确认“当前版本：1.8”，并确认“离线使用：已就绪”。检查历史覆盖范围、最近一组重量/次数/时间、最近删除、进行中的组/备注/计时，以及健康来源，均应保持。进入“健康与 AI”核对负重类型和报告。
6. 完成联网缓存后可在本人手机上测试飞行模式：重新打开应用，检查现有训练与健康记录能否查看。检查完成后恢复联网。真实 iPhone 的结果需要实际验证，桌面测试不能代替。

更新使用原站点本地存储：训练 `rainlift.web.v1`、健康 `rainlift.health.v1` 保留，新增类型 `rainlift.exercise-meta.v1`；训练 JSON 仍为 `version:1`。正常更新不清理这些存储空间，也不要求重新导入真实记录。旧训练备份不包含新增类型设置；迁移时按身份关联，不能用相同名字自动套用。

## 暂未看到新版

- 确认原网址为 https://rainrespite.github.io/rain-lift/ ，Pages发布完成后保持联网再点“检查更新”；“已完成检查”不是新版载入证明，应核对设置版本号。
- 若正在下载，等待下载完成后再刷新。网络或某个资源下载失败时，保留原可用缓存；重试检查更新即可。
- 保存编辑内容后，关闭并重新打开原主屏幕应用，再检查。若仍是 v1.7 或更早，核对该网址的部署状态与资源版本，保留旧版继续使用。
- **不要清除 Safari 网站数据、删除原图标、重置存储或导入旧备份来催促更新。** 如果出现数据不可见，先核对当前网址和使用环境，再处理，不要先恢复覆盖。

## 网址与记录的关系

GitHub Pages、OpenAI Sites 和本地预览是不同来源，各自持有当前设备的训练、健康与类型数据。Safari 与主屏幕环境也可能不同；另一个网址显示 v1.8 不会带来原入口的历史。不要向日常入口导入交付目录中的 synthetic 合成测试文件。

同一入口升级后继续使用原有记录。换网址或设备时，先分别导出训练、健康与类型备份并在目标环境核对后手动迁移。训练恢复会替换目标训练数据；类型恢复也会替换独立类型设置并保留前副本，均不是自动同步。

## v1.8 真机验收

以下事项尚未在用户 iPhone 执行。优先用专门的测试计划与测试训练，保留真实历史；不要为验收在日常环境覆盖恢复合成备份。

1. 编辑测试计划：将末项移到第一位、第五项移到第二位、首项移到最后。选择位置并保存后立即看到草稿预览；关闭取消应不改原计划，保存整个计划后重开、刷新顺序一致，其他计划不变。
2. 测试训练记录一组后填写合法重量和备注，直接打开调整动作并排序；检查选中动作、组记录、输入与休息倒计时保留。临时排序不改固定计划，只有主动点“更新固定计划”并确认才同步。
3. 健康与 AI 中确认“引体向上”“龙悬”自重类型；可以分别修改同名独立动作。68/73 kg 差异只提示核对，不写成额外负重或力量进步，冲突身份先整理再设置。
4. 生成精简报告：检查超过 7 天的历史、最近两次/基线、五部分结构、无内部 UUID/重复 JSON/虚假时长。无健康数据只一句说明；有数据核对来源和日期，不出现恢复评分。
5. 一键复制后粘贴到本地记事应用核对文本；切换详细模式、分别下载 TXT、报告 JSON、类型备份，验证 iOS 文件保存与剪贴板权限。报告 JSON 不用于恢复。
6. 等“离线已就绪”后开启飞行模式，关闭重开 PWA，验证查看记录、生成报告、类型设置与排序仍可本机保存。恢复联网后再查更新。真机触控、剪贴板/下载及飞行模式结果需实际记录，桌面窄屏不能替代。

## 健康与 GPT 的实际链路

手机应用版本更新后，健康数据仍需由用户运行 iPhone 快捷指令导出到本地文件，再在“健康与 AI”中预览并确认导入。Apple Watch 新产生的数据不会因 PWA 更新自动进入 Rain-Lift。

GPT 报告在本机生成，用户主动复制或下载后自行决定是否发送到 ChatGPT。当前版本没有跨设备记录自动同步、HealthKit/Watch 自动连接、可靠锁屏后台同步或后台上传。快捷指令配置见 [apple-health-shortcuts.md](apple-health-shortcuts.md)。
