# Rain-Lift v1.9.5 交付与恢复

## 本轮结果

动作挑选弹窗支持一次勾选多个动作，计划与本次训练不必再逐个点选。切换主类页签不会清空已选，确认后按点选顺序加入；数据格式与备份保持不变。

| 需求 | v1.9.5 行为 | 代码位置 |
| --- | --- | --- |
| 大类里多选 | 编辑计划与「调整本次训练」的「添加动作」都改为多选：每行带勾选状态，顶部提示「可勾选多个动作，切换大类会保留已选。」，按钮显示「添加动作（已选 N）」，未选时不可点。 | [计划多选](app.js#L263)、[弹窗生成](app.js#L409)、[确认按钮](app.js#L421) |
| 跨类保留已选 | 已选动作按动作编号放在本次弹窗的临时数组里；切到别的主类再切回来，标记和计数都保留。 | [页签保留](app.js#L426)、[页签绑定](app.js#L428) |
| 按点选顺序加入 | 确认时按勾选先后加入计划或本次训练，不按主类分组重排；加入后回到原编辑或调整流程。 | [计划加入](app.js#L263)、[训练加入](app.js#L434) |
| 更换动作仍单选 | 「更换动作」不显示多选提示、计数和确认按钮，点动作即替换当前行，并默认停在该动作的主类。 | [单选分支](app.js#L438) |
| 新建动作携带已选 | 多选弹窗里点「创建新动作」，已勾选的动作会在保存新动作后一起加入；新动作按原有规则进入动作库。 | [新建回传](app.js#L430)、[创建流程](app.js#L437) |
| 身份冲突先整理 | 编号存在旧历史关联冲突的动作行显示「整理」，不可勾选；确认前再次检查，发现冲突转去历史整理，不写入半套选择。 | [行状态](app.js#L416)、[训练校验](app.js#L433) |

## 数据与兼容

- 多选状态只存在于当前弹窗的内存数组，不写入 `rainlift.web.v1` / `rainlift.web.v2`，也不新增 `library`、`group` 或其他字段。
- 训练 v1/v2、动作库、分类与六分区完整备份格式均未变化，备份 `minimumAppVersion` 仍是 `1.8.2`。
- v1.9.4 的完整备份在 v1.9.5 中导入后记录完全一致；带动作库与分类的 v1.9.5 备份交回 v1.9.4 可原样读取、继续记组并再次导出。
- 训练单独导入仍整体替换训练分区，目标端原有动作库不残留；这是既有语义，本轮未改。
- 旧编号关联冲突时，多选行不可点；训练侧确认前还会整体复查一次，避免只加入一部分动作。

## iPhone 待真机验收

1. 从原主屏幕图标联网打开，等新版缓存后按提示刷新；设置核对版本为 1.9.5，历史和本次训练条数与升级前一致。
2. 编辑任一计划 → 「＋添加动作」，勾选两个动作，切到另一主类再勾一个，核对计数一直保留。
3. 确认后核对计划新增动作的顺序与勾选顺序一致；保存并重新打开计划，顺序不变。
4. 开始一次训练 → 「调整本次训练」→ 「添加动作」，同样跨主类勾选多个，确认后核对本次训练的动作数、顺序和主类标签。
5. 对任一动作点「更换」，核对没有多选计数和确认按钮，点一个动作即替换。
6. 在多选弹窗里点「创建新动作」，核对已勾选动作与新动作一起加入，且新动作进入动作库。
7. 刷新页面、切到飞行模式，核对进行中的训练和计划仍可编辑；导出完整备份并在隔离入口导入，核对动作库与分类完整。
8. 核对弹窗换行、已选行样式和点按区高度；控制台应无报错。
