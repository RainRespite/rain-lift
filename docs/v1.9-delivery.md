# Rain-Lift v1.9.0 交付与恢复

## 使用方式

在计划的动作设置中展开「渐进建议（选填）」，启用后填写目标次数范围。训练中也可以通过「调整动作 → 设置」只修改本次动作。默认关闭。目标组数、重量步长和三个快捷次数继续分别设置。

- 同重量完成普通组，且符合评分及次数条件时，建议下一组多做 1 次。例如目标 8–12 次，当前 40 kg × 8、RPE 8 时，显示「保持 40 kg，尝试 9 次」。
- 动作本次还没开始普通组时，可检查最近两次已完成的同动作训练。两次都用相同单位、外部负重、当前重量及相同目标，普通组数达标且全部达到次数上限，并有精确 RPE ≤ 8 且无力竭标记，才会提示增加一个现有步长。回看窗按训练结束时间滚动 30 天，含边界。
- 手动点「采用建议重量」才填入当前组的重量。采用时重新核对动作、历史证据、负重模式和输入，计划、次数快捷键、组记录及计时保持原有控制。建议次数可用快捷键或「其他次数」手动记录。
- 自重、辅助、旧负重语义不明、动作冲突、缺少评分或目标快照时显示原因。RIR 5+ 与待确认评分均不作加重证据。旧训练没有目标快照时，需要积累两次符合条件的新记录才能出现历史加重建议。

## 数据与发布基线

开发基线为已发布的 v1.8.6，提交 `6334d771bc5b8384ad99afa8d257931debc17753`。基线测试 282 项通过。分支为 `codex/progression-v1.9`，正式标签为 `v1.9.0`。 [基线提交](https://github.com/RainRespite/rain-lift/commit/6334d771bc5b8384ad99afa8d257931debc17753)

- `progression.js` 负责配置校验、证据评估和建议计算。训练页的现有重量预填仍由 `bodyUI.suggested` 提供，采用建议复用手动重量覆盖字段。
- 动作配置新增可选的 `progression`。启用期间每次记组在同一次提交中保存可选 `progressionTarget`，包括当时的目标组数和次数范围。训练中混用不同目标会让该次训练退出加重证据，完训时的最新设置无法追改已保存快照。
- 训练 v1/v2 权威键、完整备份六分区、恢复日志、历史原值和评分语义继续使用现有契约。新字段可选，旧记录无批量迁移。旧版追加的组保持原状，后续补评级也不会补造当时的目标快照。
- `progression.js` 随其他模块一起预缓存，设置、包版本、静态引用和缓存版本均为 1.9.0。20 个可发布文件在 `docs/` 与 `dist/` 逐字节一致。

## 恢复

Git bundle、文件校验值与验证过的独立恢复构建 `1.8.6-recovery.r190-20261105a` 位于相邻目录 `rain-lift-v1.9-recovery-20261105`。原始 v1.8.6 标签指向精确基线。可以在新目录重建恢复件。

```sh
node scripts/prepare-v1.8.5-recovery.mjs --baseline v1.8.6 --out /absolute/new-recovery-directory --build-id 190-20261105a
```

准备另一次恢复发布时使用独立构建 ID。先保存最新完整备份并关闭其他正在编辑的页面。经过隔离同源验证和明确授权，再以新的恢复提交发布原网址。原主屏幕入口保持使用，核对训练、进行中计时、最近删除、健康、档案、目标快照及离线。恢复异常时保留原存储和备份，切回能读写当前数据的已验证构建。

正式更新继续使用原 GitHub Pages，应用在联网且空闲的训练首页自动载入新版。线上文件核验与设备载入分别记录。
